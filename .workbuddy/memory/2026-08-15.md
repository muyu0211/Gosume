## Gosume 一期改造 PRD 分析 + 开发方案
- PRD：`docs/Gosume一期改造PRD.md` —— 移除每模板的 `template.html`，应用内用**一个统一 HTML** 承载数据形态/逻辑；模板只留 `json+css`，单双栏/头像靠 CSS。
- 产出方案：`docs/Gosume一期改造开发方案.md`（用户确认后未启动开发）。
- 已确认 4 个关键决策：
  1. 布局骨架 = **CSS Grid 命名区域**（统一 HTML 输出 header/aside/main 语义块，单双栏由每模板 CSS 的 grid-template-areas 决定）。
  2. 头像控制 = **仅数据存在 + CSS**，`features.avatar` 维持元数据不消费。
  3. 导入包向后兼容 = **宽松**，zip 含 template.html 则忽略，只取 css+json。
  4. 节奏 = **先样板（modern 单栏 + split 双栏）验证打通双链路，再分批迁移其余 14 套 css**。
- 关键架构事实（写方案时确认）：预览/导出/缩略图走前端 `templateEngine.ts`；后端 `HTMLRenderer`（`ResumeService.Render`）也需同步统一 HTML。两条链路都必须消费同一 `unified.html`。`features.*` 当前均未被渲染器消费；`sections.layout` 仅编辑器展示顺序、不影响渲染。
- 最大工作量：16 套内置 `styles.css` 改写为布局无关（R1）。模板生成 SKILL 不在本期（二期 PRD）。

- 两处根因串联了 6 个渲染 bug：

  - **RC2**：头像从旧模板 header 右侧挪到 `r-aside` 左侧 → 单栏下头像与邮箱手机挤一块。

## 补丁：渐变现代风内容区页边距丢失
- 现象：gradient 是"全出血"设计（.resume-page 无内边距，横向页边距在 .r-main 上），但单栏分页路径把 main.children 拍平、丢掉 .r-main 包裹层 → 内容区贴边。
- 修复（paginationCore.ts）：单栏也走"main 壳流动"——每页重建 .r-main 空壳，章节流入壳内，保留 .r-main 自身的 padding/背景；header/aside 作为页1前置块只放一次。newPage 统一（双栏加侧栏壳，两种模式都加 main 壳）。vite build 通过。
- 教训：分页算法切分内容时必须保留"内容包裹层（.r-main）"本身，不能只取 children，否则依赖包裹层内边距/背景的模板（全出血布局）会丢边距。

## 补丁2：渐变现代风全出血导致的分页/导出问题
- 现象：PDF 续页无顶边距+生硬截断、PNG 页间/页尾空白（其他模板正常）。
- 根因：gradient 是"全出血"设计——页边距不在 .resume-page 而是分散在 .r-header/.r-aside/.r-main 各区块自身 padding。分页/导出管线只把 .resume-page 的 padding 当"页边距"消费/折叠：续页无 header 带 → 无顶边距；PNG 连续渲染只折叠 .resume-page 上下 padding，折叠不了 .r-main 的 12mm 底边距 → 页间/页尾空白。
- 修复：gradient 回归标准页边距模型（.resume-page { padding: var(--resume-padding, 12mm 14mm) }），头部渐变带退化为页面内"渐变卡片"，去掉各区块的补偿 padding。
- 已在 templates/AGENTS.md 加硬规则：**单栏模板页边距必须落在 .resume-page padding，不得落在内容区自身 padding；需要全出血头部时也不得用负 margin 拉出页面**（会破坏分页测量与 PNG 连续渲染），应退化为页面内色块/卡片。
- 验证：go build + go test 通过。
