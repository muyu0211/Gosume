# 2026-08-17

## 体验优化：macOS 原生红绿灯标题栏

问题：所有平台统一 `frameless: true` + 前端自绘右侧三键（横杠/方框/×），macOS 上无原生红绿灯，看起来像 Windows 程序。

方案（Wails v3 alpha.85 验证）：
- macOS 下 `Frameless: true` 会变成 `NSWindowStyleMaskBorderless` → 红绿灯整个消失（根源）。
- 修复：`pkg/app/app.go` 中 darwin 分支设 `Frameless=false` + `Mac.TitleBar = application.MacTitleBarHiddenInset`（透明标题栏+隐藏标题+FullSizeContent+toolbar），红绿灯为原生，标题栏条原生可拖拽、双击原生缩放。
- 前端：新增 `frontend/src/lib/platform.ts`（优先 `_wails.environment.OS`，兜底 UA），main.tsx 渲染前写入 `<html data-platform>`；App.tsx 的 `SetFrameless(true)` 兜底改为仅非 darwin 生效（否则会再干掉红绿灯）；TitleBar.tsx 在 macOS 不渲染自绘按钮、跳过 IsWindowMaximised 查询；globals.css 加 `.platform-darwin` 规则（隐藏按钮 + 左侧 padding 84px 避让红绿灯）。

关键坑：
- 前端构建时 vite 清空 dist 会被环境的安全删除 shim 拦截（trash 失败）；先手动确认 dist 已删/重命名即可（本次实际是 rm 成功后 shim 误报）。
- `go build ./...` 的 `build/ios` 缺 main 报错为仓库既有问题，与本改动无关。
- tsconfig 的 TS5101/TS6310 报错为既有配置问题（TS6 + baseUrl），与代码无关。

验证：`go build ./pkg/...`、`go vet ./pkg/app/`、`go build .`、前端 `vite build` 全部通过。Windows 路径行为不变。

## Bug 修复：macOS 红绿灯与标题 "Gosume" 重叠

根因：`platform.ts` 只写了 `data-platform` 属性，而 globals.css 用的是 `.platform-darwin` 类选择器，类从未被设置 → 84px 避让 padding 没生效。

修复：`applyPlatformToDocument()` 同时添加 `platform-{os}` class；CSS 规则追加 `[data-platform='darwin']` 属性选择器双保险。前端已重新构建。

## 修复：service 包迁移到 pkg/resume/service 后前端全部接口失联

根因：Wails v3 方法绑定 FQN = `{packagePath}.{TypeName}.{MethodName}`（bindings.go 的 `getMethods` 用 `namedType.PkgPath()` 拼装，与 `ServiceName()` 接口无关）。用户把 service 从 `pkg/service` 挪到 `pkg/resume/service` 后，后端绑定名变为 `gosume/pkg/resume/service.XXXService.Method`，而前端 `backend.ts` 仍硬编码旧前缀 `gosume/pkg/service` → 所有接口 `unknown bound method name`。

修复：`frontend/src/services/backend.ts:39` 的 FQN 前缀改为 `gosume/pkg/resume/service`。所有前端调用都经 `callService` 唯一出口，改一处即覆盖全部接口。前端已重建、`go build ./pkg/...` 通过。

坑：vite 构建清空 dist 会被安全删除 shim 拦截报错，需先手动 `rm -rf dist`（纯构建产物，安全）再 build。

## 修复：查看简历报「加载简历失败」（version 字段被 App 版本号污染）

根因：`Resume.Version` 本应是数据 schema 版本（`model.Migrate` 只认 `"1.0"`），但 `NewResume` 写入了 `config.GlobalConfig.App.Version`（当前为 `1.0.0`）。config 版本从 `1.0` 改为 `1.0.0` 后，新建简历落库 `"version":"1.0.0"`，`Migrate` 报 `unsupported data version: 1.0.0` → 包装为「加载简历失败」。前端 sampleData 一直是 `1.0`，所以只有 Go `NewResume` 新建的空白简历受影响。

修复：
- `pkg/resume/model/resume.go`：新增 `SchemaVersion = "1.0"` 常量；`Migrate` 的 switch 接受 `"1.0"` 和 `"1.0.0"`，并统一规范化 `r.Version = SchemaVersion`（历史误写数据向后兼容）。
- `pkg/resume/service/resume_service.go`：`NewResume` 改为 `Version: model.SchemaVersion`，移除不再使用的 `config` import。

验证：`go build ./pkg/...`、`go build .` 通过；用临时 Go 程序直读真实 DB（`AppData/Roaming/ResumeCraft/data/gosume.db`）逐条跑 `Migrate`，唯一活跃简历 `81f1b996`（1.0.0）已能成功加载并规范化为 1.0。另：库里 36 条历史记录是 `is_deleted=1` 软删除，不影响「全部简历」列表，非本次问题。

注意：本次重构把 `Resume.Summary/SummaryHidden` 换成了 `PersonalSummary`（json `personal_summary`，一期改造），旧数据这两个字段会被 json 静默忽略——旧简历的个人总结文本会丢失，属已知迁移缺口，未在本次处理。
