# 2026-08-16 工作日志

## 合并 header/aside 后 bug 修复：r-contact 未渲染

**现象**：部分模板个人信息区只显示头像/姓名/职位/年限，邮箱手机（r-contact）不渲染。

**根因（两层）**：
1. **前端 glob 路径错误**（核心 bug，一期改造时埋下）：`frontend/src/services/templateService.ts` 里 4 个 `import.meta.glob` 用 `'../../templates/...'`，从 `frontend/src/services/` 出发指向 `frontend/templates/`（**不存在**），而模板实际在项目根目录 `templates/`。正确应为 `'../../../templates/...'`。导致 dev 模式下 `unified.html` 及各模板 CSS **根本没打包进 dist**（dist 里 `r-contact`/`r-name` 计数为 0）。
2. **前端 build 未完成**：上一轮合并改动后，前端 build 因 vite 清 dist 被沙箱拦截而失败，dist 停留在旧版本。

**修复**：
- `templateService.ts` 4 个 glob 路径 `'../../templates/'` → `'../../../templates/'`。
- 重新 `npm run build`（需 `rm -rf dist` + 绕过沙箱），dist 里 r-contact 计数从 0 → 73。
- 重新 `go build`（嵌入新 dist）。

**教训**：
- `import.meta.glob` 相对路径是**相对于当前文件**（不走 vite alias），`frontend/src/services/` 到项目根目录需三层 `../`。
- 前端 build 用 vite 会清 dist，沙箱 safe-delete 会拦截 `rmSync`，必须 `rm -rf dist` 后 `dangerouslyDisableSandbox` 构建。
- 诊断渲染类 bug：可用 Go 侧 rod（`pkg/export/browser.go` 的 BrowserManager）实际渲染验证 computed style / gridArea / 可见性，比纯静态分析可靠。

## 白屏 bug：glob 返回值是冻结的 module 命名空间对象

**现象**：修复 r-contact（glob 路径 `../../` → `../../../`）后，应用重启**白屏**（#root 完全空）。

**根因**：`import.meta.glob` 默认（**不加 `import: 'default'`**）返回的是 **module 命名空间对象**，且被 Vite 编译成 `Object.freeze(...)`。之前 glob 指向空目录（`frontend/templates/` 不存在）→ `buildTemplateMap` 的 for 循环不执行、不触发；改成 `../../../templates/` 匹配到 16 个模板后，`buildTemplateMap` 里 `meta.is_builtin = true` 对**冻结对象赋值**，在 ES module 严格模式下抛 `TypeError: Cannot add property is_builtin, object is not extensible`，模块顶层抛错 → bundle 加载失败 → 白屏。

**修复**：4 个 glob 都加 `import: 'default'`，让值变成可修改的 JSON 对象 / `?raw` 字符串（而非冻结命名空间对象）。dist 从 1.15MB 降到 681KB（不再生成命名空间包装）。

**教训**：
- `import.meta.glob(..., { eager: true })` 默认返回 `{ default: X, ...命名导出 }` 的**冻结** module 命名空间对象；要直接拿 default 导出必须加 `{ import: 'default' }`。对 glob 结果做任何**写操作**（如 `meta.is_builtin = true`）会抛 TypeError。
- rod 的 `page.EvalOnNewDocument(script)` 要传**直接 JS 代码**，不是箭头函数 `() => {...}`（箭头函数只定义不执行，导致"无错误"是假象、误判了方向）。

## PNG 导出空白 bug（双栏页尾 + 深色模板白色条带）

**现象**：① 双栏模板（split/creative）PNG 导出页尾大量空白；② 深色模板（terminal）PNG 导出页顶/页间/页尾有白色空白。

**根因**（都在 `pkg/export/browser.go` 的 `pngContinuousCSSJS` 注入脚本）：
1. 双栏模板 `.resume-container` 是 `display:grid` + `min-height:297mm`（为了让侧栏通高）。PNG 连续渲染脚本只重置了 `.resume-page` 的 `min-height/height`，**没重置 `.resume-container`** → 每页仍被 grid 容器撑到 297mm → 页尾空白。
2. 脚本把页边距从 `.resume-page`（padding）移到 `.resume-pages-wrapper`（padding-top/bottom），但 wrapper 背景是**透明**的（透出 body 白色），深色模板首尾/页间就露出白色条带。

**修复**：`pngContinuousCSSJS` 里 ① 读页面背景色 `cs.backgroundColor`；② 追加 `.resume-container{min-height:0 !important;height:auto !important}`；③ 给 `.resume-pages-wrapper` 加 `background:<pageBg> !important`。

**验证**：rod 构造"分页后" HTML 注入脚本，测量 page 高度从 297mm 收缩到内容高度（300px/120px）、页间 top==上一页 bottom（无空隙）、wrapper 背景变深色 `rgb(13,17,23)`。

**教训**：PNG"连续渲染"（多页拼一张长图）靠注入 CSS 收缩 `.resume-page`，任何在**内层容器**上写 `min-height`（如 grid 双栏通高、单栏全出血）的模板，都必须同步在该脚本里重置，否则收缩失效；首尾/页间空白是"背景色"问题——wrapper 背景要跟随页面背景色，不能依赖透明透出 body。

## 追加：pngContinuousCSSJS 的 JS 字符串被拆行导致 SyntaxError

**现象**：修复后运行时仍报 `PNG导出: 浏览器截图失败: 注入连续渲染 CSS 失败: eval js error: SyntaxError: Invalid or unexpected token`。

**根因**：`pngContinuousCSSJS` 里 `style.textContent = '.resume-page{...}...'` 这段 JS 单引号字符串，被**某格式化工具/IDE 保存时格式化**拆成了多行（CSS 选择器换行+缩进），JS 单引号字符串**不能跨行**（除非 `\` 续行），导致 rod 的 `page.Eval` 抛 SyntaxError。Go 侧 `go build` 仍能过（反引号原始字符串跨行合法），所以编译通过≠JS 合法。

**修复**：用 Python 脚本把 `style.textContent` 从 `start_marker` 到 `}';` 之间整体替换回**单行**字符串，再 `gofmt -w`（gofmt 对字符串字面量不透明、不会拆行，安全）。

**教训**：
- Go 反引号字符串里内嵌 JS/CSS，**单引号字符串必须单行**；排查 `page.Eval` 报 `SyntaxError` 时，用 `sed -n 'N,Mp' file.go | cat -A` 看原始字节（`^I` 是 Tab），或直接 rod 实测注入来验证。
- `go build` 通过只证明 Go 编译合法，**不证明内嵌 JS 合法**；这类"JS 藏在 Go 字符串里"的改动，验证要以"rod 实际 `page.Eval` 注入成功"为准。
