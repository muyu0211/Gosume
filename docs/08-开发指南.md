# 08 — 开发指南

## 8.1 环境要求

| 工具 | 最低版本 | 说明 |
|------|----------|------|
| Go | 1.22+ | Go 语言编译环境 |
| Node.js | 18+ | 前端构建运行时 |
| pnpm | 8+ | 前端包管理器 |
| Wails CLI | v3+ | `go install github.com/wailsapp/wails/v3/cmd/wails3@latest` |
| WebView2 | 预装 | Win11 已内置，Win10 需[手动安装](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) |
| golangci-lint | v1.59+ | Go 代码质量检查 |
| Git | 2.40+ | 版本控制 |

### 8.1.1 验证环境

```bash
go version          # go version go1.22.x windows/amd64
node --version      # v18.x.x
pnpm --version      # 8.x.x
wails3 version      # v3.0.0-alpha.x
wails3 doctor       # 检查所有依赖是否就绪
```

## 8.2 项目初始化

### 8.2.1 创建项目

```bash
# 使用 Wails v3 CLI 初始化项目（选择 React + TypeScript + Vite 模板）
wails3 init -n resume-craft -t react-ts

cd resume-craft

# 安装前端依赖
cd frontend && pnpm install && cd ..

# 安装 Go 依赖
go mod tidy
```

### 8.2.2 安装前端额外依赖

```bash
cd frontend

# UI 组件
pnpm add react-router-dom zustand react-hook-form @hookform/resolvers zod
pnpm add @tiptap/react @tiptap/starter-kit @tiptap/extension-placeholder
pnpm add @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities
pnpm add lucide-react

# Tailwind CSS
pnpm add -D tailwindcss postcss autoprefixer
npx tailwindcss init -p

# shadcn/ui 初始化
npx shadcn-ui@latest init

# 代码质量
pnpm add -D eslint prettier eslint-config-prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin

cd ..
```

### 8.2.3 安装 Go 依赖

```bash
# Wails v3 核心
go get github.com/wailsapp/wails/v3

# 模板函数扩展
go get github.com/Masterminds/sprig/v3

# 无头浏览器（PDF/PNG）
go get github.com/go-rod/rod

# DOCX 模板填充
go get github.com/otfot/docxr

# 测试
go get github.com/stretchr/testify

# 清理
go mod tidy
```

### 8.2.4 生成前端绑定

```bash
# Go 服务方法变更后，重新生成 TypeScript 绑定文件
wails3 generate bindings

# 生成文件位置: frontend/bindings/resume-craft.ts
```

## 8.4 开发工作流

### 8.4.1 启动开发服务器

```bash
# 在项目根目录运行
wails3 dev

# 这会：
# 1. 编译 Go 后端并启动
# 2. 启动 Vite 开发服务器（HMR）
# 3. 自动生成前端 TypeScript 绑定（frontend/bindings/）
# 4. 打开 Wails 桌面窗口
# 5. 前端代码修改 → 浏览器秒级热更新
# 6. Go 代码修改 → 自动重新编译并重启
```

### 8.4.2 日常开发流程

```
┌──────────────────────────────────────┐
│  修改前端代码 (.tsx, .css)            │
│  → Vite HMR 即时更新（无需重启应用）   │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│  修改 Go 代码 (.go)                   │
│  → 保存后应用自动重新编译并重启        │
│  → 约 2-5 秒                          │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│  修改 Go 服务方法签名                  │
│  → 运行 wails3 generate bindings     │
│  → 或重启 wails3 dev（自动重新生成）   │
└──────────────────────────────────────┘
```

### 8.4.3 代码检查

## 8.5 构建与打包

### 8.5.1 开发构建

```bash
# 构建当前平台的可调试版本
wails3 build -debug

# 产物：./build/bin/resume-craft.exe (Windows)
```

### 8.5.2 生产构建

```bash
# 构建当前平台
wails3 build -clean -platform windows/amd64

# 构建所有平台
wails3 build -clean -platform windows/amd64,darwin/amd64,darwin/arm64,linux/amd64

# 产物位置：
# Windows: ./build/bin/resume-craft.exe
# macOS:   ./build/bin/resume-craft.app
# Linux:   ./build/bin/resume-craft
```

### 8.5.3 安装包制作

**Windows (NSIS)**：

```bash
# 安装 NSIS 后
wails3 build -clean -platform windows/amd64 -nsis

# 产物：./build/bin/resume-craft-amd64-installer.exe
```

**macOS (DMG)**：

```bash
wails3 build -clean -platform darwin/amd64 -dmg
```

### 8.5.4 体积优化

| 优化项 | 方法 | 预计减小 |
|--------|------|----------|
| UPX 压缩 | `wails3 build -upx` | -30%~50% |
| 移除调试符号 | `wails3 build -clean` | 默认包含 |
| 使用系统 Chrome | 配置 go-rod 使用系统已安装 Chrome | -150MB（最显著） |
| 前端 Tree shaking | Vite 默认开启 | - |

```go
// 配置 go-rod 使用系统 Chrome 以减小打包体积
// pkg/render/pdf.go
import "github.com/go-rod/rod/lib/launcher"

func NewBrowser() *rod.Browser {
    // 优先查找系统 Chrome/Edge
    path, found := launcher.LookPath()
    if found {
        u := launcher.New().Bin(path).MustLaunch()
        return rod.New().ControlURL(u).MustConnect()
    }
    // 回退到 go-rod 自带的 Chromium
    return rod.New().MustConnect()
}
```

## 8.6 项目开发阶段

### Phase 1: 项目骨架（预计 1-2 周）

- [ ] Wails v3 项目初始化（`wails3 init`）
- [ ] Go 数据模型实现（`pkg/model/`）
- [ ] 前端路由与基础布局（WelcomePage, EditorPage, SettingsPage）
- [ ] 状态管理 Store 搭建（Zustand stores）
- [ ] 服务注册框架搭建（`application.NewService()` + `wails3 generate bindings` 验证）

### Phase 2: MVP 核心功能（预计 3-4 周）

- [ ] 1 套内置模板（modern 风格）
- [ ] 结构化表单（Personal + Job + Education + Skills）
- [ ] HTML 渲染引擎（Go html/template → HTML 字符串）
- [ ] 实时预览面板（iframe 渲染，debounce 刷新）
- [ ] 项目文件读写（.resume.json 打开/保存/另存为）
- [ ] 自动保存

### Phase 3: 导出功能（预计 2-3 周）

- [ ] PDF 导出（go-rod 方案）
- [ ] PNG 导出（go-rod 截图）
- [ ] DOCX 导出（docxr 模板填充）
- [ ] 导出对话框 UI + 进度反馈（通过 `app.Event` 管理器发送事件）

### Phase 4: 多模板与完善（预计 3-4 周）

- [ ] 5 套内置模板

- [ ] 模板导入/删除
- [ ] 模块拖拽排序（@dnd-kit）

### Phase 5: 测试、打包、发布（预计 2-3 周）

- [ ] 单元测试与集成测试

- [ ] 自动更新集成
- [ ] 发布 v1.0

## 8.7 Git 工作流

### 8.7.1 分支策略

```
main              # 稳定发布分支
├── develop       # 开发主线
│   ├── feat/xxx  # 功能分支
│   └── fix/xxx   # Bug 修复分支
└── release/v1.x  # 发布准备分支
```

### 8.7.2 Commit 规范

使用 Conventional Commits：

```
feat: 添加 PDF 导出功能
fix: 修复技能等级条在预览中显示不正常的问题
docs: 更新为 Wails v3 技术文档
refactor: 重构模板加载器，提取接口
test: 添加数据模型序列化测试
chore: 升级 Wails 到 v3.0.0-alpha.50
```

## 8.8 调试技巧

### 8.8.1 Go 后端调试

```bash
# 以 debug 模式启动（打开浏览器开发者工具）
wails3 dev -d

# 在代码中打印调试信息（v3：通过 app.Log 管理器）
import "github.com/wailsapp/wails/v3/pkg/application"

app.Log.Info(fmt.Sprintf("current resume: %+v", resume))
app.Log.Warning("export timeout, retrying...")
app.Log.Error(err.Error())
app.Log.Debug("detailed diagnostic info")
```

### 8.8.2 前端调试

在 Wails 开发模式下，右键点击应用窗口 → 选择"检查"（Inspect），即可打开 Chrome DevTools。

或者在 `wails3 dev` 时添加 `-d` 参数自动打开 DevTools。

### 8.8.3 常见问题

| 问题 | 解决方案 |
|------|----------|
| `wails3 dev` 报 WebView2 错误 | 安装 [WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) |
| 前端绑定类型报错 | 运行 `wails3 generate bindings` 重新生成 |
| go-rod 下载 Chromium 失败 | 设置代理或手动下载，或配置使用系统 Chrome |
| 中文在 PDF 中显示为方块 | 检查 CSS `font-family` 是否包含中文字体 |
| `application.New` 参数类型不匹配 | 检查 Wails v3 alpha 版本，Options 字段可能以指针或值传递 |

## 8.9 文档维护

- 所有技术文档存放在 `docs/` 目录
- 文档随代码变更同步更新
- Go 模型变更必须同步更新前端 TypeScript 类型定义
- 模板规范变更必须发布 changelog（供模板开发者参考）
- Wails v3 API 尚在 alpha 阶段，文档中的 API 以 `v3.0.0-alpha.50+` 为基准，升级版本时需检查 breaking changes
