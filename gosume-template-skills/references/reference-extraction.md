# 从参考素材生成模板

当用户传入简历图片、PDF 或其他格式的简历模板作为参考时，按本文档提取风格特征并映射到 Gosume 数据模型。

## 输入类型与处理方式

| 输入类型 | 处理方式 |
|----------|----------|
| 图片（jpg/png/gif/webp） | 用 `read_file` 工具读取，AI 直接视觉分析 |
| PDF | 先用 `pdf` skill 提取文本和布局信息；若有截图/预览图则一并视觉分析 |
| HTML 文件 | 用 `read_file` 读取，分析结构和样式 |
| Word/其他格式 | 请求用户转成 PDF 或截图 |

> 关键原则：**参考素材只是风格参考，最终模板必须符合 Gosume 的数据模型和校验规则**。用户传入的简历可能字段名不同、区块结构不同，必须做映射。

## 风格提取清单

分析参考素材时，提取以下要素。建议向用户复述确认后再动手写代码。

### 1. 整体布局

判断属于哪种布局模式：

| 布局 | 特征 | 映射建议 |
|------|------|----------|
| 单栏 | 所有内容纵向排列 | 最常见，直接采用 |
| 双栏（左侧栏） | 左侧窄栏放联系方式/技能，右侧宽栏放经历 | 侧边栏放 skills/languages/contact，主体放 jobs/projects/education |
| 双栏（右侧栏） | 右侧窄栏 | 同上但方向相反 |
| 头部+主体 | 头部横跨全宽，下方单栏或分栏 | header 用 border-bottom 分隔 |
| 三栏/网格 | 复杂网格布局 | 简化为双栏或单栏，Gosume 不适合过于复杂的网格 |

> 若参考素材是三栏或复杂网格，主动告诉用户会简化为双栏，因为 A4 打印宽度有限（174mm 可用），栏数过多会导致内容拥挤。

### 2. 配色方案

提取主色、辅色、文字色、背景色、强调色。

**提取方法**：
- 图片：直接观察主色调，用取色思路描述（如"深蓝主色 #1E3A8A"）
- PDF/HTML：若有明确色值直接记录，否则观察

**必填 5 色**（对应 `template.json` 的 `colors`）：

| 字段 | 用途 | 提取要点 |
|------|------|----------|
| `primary` | 主色（标题、强调） | 参考素材中标题、章节标题的颜色 |
| `secondary` | 辅色 | 次级标题、分隔线颜色 |
| `text` | 正文颜色 | 主体文字颜色，通常深灰 |
| `background` | 背景色 | 页面背景，通常白色 |
| `accent` | 强调色（浅色块） | 侧边栏背景、卡片背景等浅色区域 |

**注意事项**：
- 所有颜色必须为 6 位 HEX 格式 `#RRGGBB`
- 正文色与背景色对比度需达标（WCAG AA：正文 ≥ 4.5:1）
- 如果参考素材是黑白纯色简历，`primary` 和 `secondary` 用深灰阶（如 `#1F2937`、`#374151`）

### 3. 字体特征

Gosume 只能用系统字体，不能引用外部字体。根据参考素材的字体感觉选择：

| 参考字体感觉 | 推荐字体栈 | 对应 `--font-family` |
|--------------|-----------|---------------------|
| 现代无衬线 | 苹方/微软雅黑系 | `'PingFang SC', 'Microsoft YaHei', 'Noto Sans SC', sans-serif` |
| 正式衬线 | 宋体系 | `'Noto Serif SC', 'SimSun', 'PingFang SC', serif` |
| 极客等宽 | 等宽体 | `'JetBrains Mono', 'Consolas', 'Microsoft YaHei', monospace` |

> 如果参考素材用了特殊字体（如手写体、艺术字），告诉用户无法完全还原，会改为最接近的系统字体。

### 4. 章节标题样式

观察参考素材的章节标题（如"工作经历""教育背景"）的呈现方式：

| 样式 | CSS 实现 |
|------|----------|
| 大写字母 + 字间距 | `text-transform: uppercase; letter-spacing: 1.5pt;` |
| 底部细线 | `border-bottom: 0.75pt solid var(--border-color);` |
| 左侧色块 | `border-left: 3pt solid var(--primary-color); padding-left: 8pt;` |
| 背景色块 | `background: var(--accent-bg); padding: 4pt 8pt;` |
| 居中加粗 | `text-align: center; font-weight: 700;` |

### 5. 经历条目布局

观察工作经历、项目经历等条目的排版：

| 要素 | 观察点 |
|------|--------|
| 标题行 | 公司名和职位是否在同一行？日期是右对齐还是另起一行？ |
| 日期格式 | 是范围（2020.01 - 2023.06）还是单日期？是否显示"至今"？ |
| 描述 | 概述用段落还是列表？亮点用项目符号还是横线？ |
| 项目符号 | 圆点、横线、方框、自定义符号？ |

### 6. 头像处理

判断参考素材是否有头像，以及位置：

| 情况 | 处理 |
|------|------|
| 无头像 | `features.avatar: false`，模板不渲染头像 |
| 圆形头像在左上角 | `features.avatar: true`，CSS 用 `border-radius: 50%` |
| 方形头像在头部 | `features.avatar: true`，CSS 用 `border-radius: 4pt` |
| 头像在侧边栏顶部 | 双栏布局，头像放 sidebar 顶部 |

### 7. 技能展示

| 展示方式 | 对应实现 | `features.skill_bars` |
|----------|----------|----------------------|
| 进度点（5 格） | `{{skillLevel .Level}}` | `true` |
| 进度条 | Gosume 不直接支持，用 CSS 模拟（不推荐） | — |
| 标签云 | 纯文字罗列，不显示等级 | `false` |
| 分类列表 | 按分组罗列技能名 | `false` |

> 如果参考素材用了进度条，建议改为进度点（Gosume 内置支持），并告知用户。

## 字段映射规则

参考素材的简历内容**不需要原样搬运**——模板是给空简历用的，我们只参考**结构和风格**，不复制具体数据。但需要确保模板能正确渲染各类简历数据。

### 区块映射

参考素材的章节标题可能用词不同，映射到 Gosume 的区块：

| 参考素材常见标题 | Gosume 区块 | 模板路径 |
|------------------|------------|----------|
| 个人信息/联系方式/基本信息 | personal | `.Personal` |
| 个人简介/自我评价/总结 | summary | `.Summary` |
| 工作经历/工作经验/职业经历 | jobs | `.Jobs` |
| 实习经历/实习经验 | internships | `.Internships` |
| 项目经历/项目经验/主要项目 | projects | `.Projects` |
| 教育背景/教育经历/学历 | education | `.Education` |
| 专业技能/技能特长/技术栈 | skills | `.Skills` |
| 语言能力/语言水平 | languages | `.Languages` |
| 奖项/荣誉/获奖经历 | awards | `.Awards` |
| 兴趣爱好/证书/其他 | custom | `.Custom` |

### 字段映射

参考素材中常见字段到 Gosume 字段的映射：

#### Personal

| 参考素材常见字段 | Gosume 字段 |
|------------------|------------|
| 姓名/名字 | `.Personal.FullName` |
| 英文名 | `.Personal.EnglishName` |
| 邮箱/Email | `.Personal.Email` |
| 电话/手机 | `.Personal.Phone` |
| 微信 | `.Personal.Wechat` |
| QQ | `.Personal.QQ` |
| 所在地/城市/地址 | `.Personal.Location` |
| 个人网站/主页 | `.Personal.Website` |
| GitHub | `.Personal.GitHub` |
| LinkedIn | `.Personal.LinkedIn` |
| 头像/照片 | `.Personal.Avatar` |
| 求职意向/职位/目标岗位 | `.Personal.JobTitle` |
| 工作年限/经验 | `.Personal.YearsOfExp` |

#### Job/Internship

| 参考素材常见字段 | Gosume 字段 |
|------------------|------------|
| 公司/单位 | `.Company` |
| 职位/职务/岗位 | `.Title` |
| 开始时间 | `.StartDate` |
| 结束时间 | `.EndDate` |

#### Project

| 参考素材常见字段 | Gosume 字段 |

## 处理参考素材中的特殊元素

### 图标

参考素材可能在联系方式前加图标（邮箱图标、电话图标）。Gosume 模板不能引用外部图标库，处理方式：

1. **省略图标**：只显示文字（最简单，推荐）
2. **用 Unicode 符号**：如 `✉` `☎` `⌂`（兼容性好，但样式有限）
3. **用 CSS 伪元素绘制简单图形**：如圆点、方块（仅限极简图形）

### 二维码

参考素材若有二维码，Gosume 的 `features.qr_code` 字段可标记，但模板本身不生成二维码。建议省略，告知用户。

### 装饰性图形

参考素材可能有背景花纹、几何装饰。处理原则：

- 简单的色块、线条可用 CSS 实现
- 复杂图形无法还原，省略并告知用户
- 不得引用外部图片资源

### 多页设计

参考素材若是多页简历，注意：

- Gosume 模板是单页设计，内容超出会自动分页（通过 `.page-break` 类控制）
- `page_count` 字段描述支持的页数范围
- 不要试图在模板中硬编码"第二页"结构

## 与用户确认的要点

分析完参考素材后，向用户复述以下理解，确认后再写代码：

1. **布局判断**："我看出这是单栏/双栏布局，侧边栏放 X，主体放 Y"
2. **配色提取**："主色是 #XXXXXX，辅色是 #XXXXXX，对吗？"
3. **字体感觉**："整体偏现代/正式/极客风格"
4. **章节顺序**："章节顺序是：个人信息 → 工作经历 → 项目 → 教育 → 技能"
5. **特殊处理**："参考素材中的图标/二维码/装饰图无法完全还原，会简化为 X"
6. **字段映射**："参考素材的'职责描述'会映射到工作经历的 Summary 字段，'成果'映射到 Highlights 列表"

如果参考素材与 Gosume 模型差异较大（如三栏布局、大量图标、特殊字体），主动告知用户哪些能还原、哪些需要简化，让用户有合理预期。

## 常见参考素材类型应对

### 学术简历（CV）

特征：正式、衬线字体、publication 列表
映射：publication 放 `.Custom` 区块（标题"发表论文"），每条作为 CustomItem

### 设计师简历

特征：彩色、图形化、作品集链接
映射：作品集链接放 `.Projects[].URL`；彩色配置保留但确保打印友好

### 技术简历

特征：技能突出、项目详细、技术栈明确
映射：技术栈用 `.Projects[].Extras` 键值对展示

### 应届生简历

特征：教育靠前、实习经历、课程项目
映射：layout 把 education 放前面；实习用 `.Internships`；课程项目用 `.Projects`
